## ver71 — 部品集めで個数の読取一致を必須に

コードが一致すると計量器の個数読取画面を開きます。数字だけを調整可能な枠に入れて「枠の中を読む」を押すと、別々のライブ映像で2回続けて必要数と一致した場合だけ、その個数行を確認済みにします。全行が一致すると「次へ」を有効にします。異なる数・読取不可・カメラエラーでは進めません。旧来のタップで個数チェック／「これでOK」による手動承認は廃止しました。

50台単位の自動分割や `300+210` の明示分割は維持し、箱ごとに別の読み取り操作を求めます。1箱目の成功を他の箱へ流用しません。バーコードなしの既存経路でも個数OCRは必須で、さらに品名確認が必要です。必要数が未登録または数字1〜7桁以外の場合は照合せず、登録画面へ戻るよう案内します。

ver70の数字抽出・桁数検査・7の形状補正を `quantity-ocr.js` に共通化し、本番照合と独立テスト画面で同じ処理を使用します。必要数はOCRの候補選択に渡さず、読取後に照合します。テスト画面の採点・画像付きJSON・保存先は維持します。作業中の読取では正解ラベルを作らず、テスト履歴にも混ぜません。地図・部品登録のデータ構造や保存先は変更しません。

キャンセル・やり直し・画面移動・バックグラウンド移行でカメラを止め、進行中の古いOCR結果を無効化します。復帰時は改めて読み取ります。2回一致は一時的な読み違いを減らすための条件で、繰り返す誤読や重さ欄を映した場合を完全には防げません。必ず計量器の「個数」表示を枠に合わせてください。

検証：`tests/quantity-picking-browser.cjs` で模擬OCR・模擬カメラによるコード照合、不一致／読取不可、2回一致、箱単位、キャンセル／やり直し、次の部品の状態初期化、未登録数、手動コード経路、カメラ拒否・再開・停止、スマホ幅を確認。`tests/quantity-read-browser.cjs` で既存の採点・訂正・保存・書き出しを確認。`tests/quantity-ocr-browser.cjs` で数字形状回帰を確認し、今回提供されたver70の正解判定済み14枚を実Tesseract.js 5.1.1で再読取して全件一致しました。読取不可や未採点の画像はこの14件に含みません。Pixel実機での新しい一連の操作・速度は未検証です。

## ver70 — 個数読取テストの枠線除去・70誤読対策

個数読取テストの数字抽出を、同じ高さで並ぶ文字成分を選び、選んだ成分だけを描画する方式に変更しました。小さい単位文字や枠線を桁数から除き、数字同士が細い線でつながる場合は分離します。暗い背景の成分数を表示数字の桁数として優先する処理を廃止し、位置の合う黄色・赤色／明部の数字列で照合します。

細長い表示数字を横方向に1.6倍に正規化し、行として読めない場合は単語モードで再試行します。OCRが `1` を返した部分について、上部の横棒・細い斜線・下部の位置が `7` の条件を満たすときに補正します。元のOCR文字列、再試行、形状判定、補正内容はJSONに残します。ROIの端で数字が切れた可能性がある場合は撮り直しを案内します。

`tests/quantity-ocr-browser.cjs` は枠線・短い単位文字の除去、通常体／斜体／セリフ体の `1` を `7` にしないこと、1〜7桁、先頭ゼロと形状補正を検証します。`QUANTITY_TEST_FILE` に記録JSONを指定すると実OCRで正解入力済みの全画像を照合します。写真はリポジトリに含めません。`tests/quantity-read-browser.cjs` で採点・保存・再読込・画像付き書き出し・カメラ停止も確認しました。

- 「部品」でコードを入力・貼り付け、または数字パッドで検索すると、登録場所の近くへ移動し、赤い矢印と枠で場所を示します。複数の登録先は「次の場所」で順に表示します。別フロアにも対応します。
- 「＋ 場所登録」→黒いパレットをタップ→コードと置き方を入力→「ここに登録」。既存のほかの登録場所は残ります。同じコード・同じ位置は置き方を更新します。移動元の解除は「全体」→部品を検索→「場所を移動・解除」で行えます。
- 地図のパレット表示1個＝内部の方眼2×2マス。区画の端では幅・奥行きを切り詰め、地図と一致させます。パレットが表示されない区画は、2Dマップで選択して「3D形状」から設定できます。
- 「棚番の品」のようにまとめて描いた区画は、一つの区画として表示します。個別の棚や棚段は推測しません。

この表示は**地図を基準にした3Dモデル**です。写真の緑の床・黒い樹脂パレット・蛍光灯を参考に外観を作っており、実写360°写真や写真測量による再現ではありません。高さや建物の外観は模式的です。私物の写真や動画は含みません。

部品・箱の外観は背景に含めないので、部品が入れ替わっても撮り直し不要です。実物を移動したときは場所の登録を更新してください。地図そのものやパレットの配置が変わった場合は、地図の更新が必要です。赤い矢印は登録された平面位置を示し、棚段や在庫数量を保証するものではありません。

## 既存データ

保存先はこれまで通りブラウザのlocalStorage（`pickingDB_v1`）です。アップデートで既存の地図・部品・天井番号を初期化しません。画像で送られた地図を別の初期地図に置き換えることもありません。複数端末の自動共有はありません。

C4765とC00004765は同じ部品として検索できます。別品番への誤案内を避けるため、ゼロ埋めを除いた完全一致です。明示的に解除した場所を旧形式の棚情報から復活させません。

3DエンジンはThree.js r128をvendor配下に同梱しています。GitHub PagesのHTML/JSのみで動作し、3D用のサーバーや外部APIは不要です。バーコード・OCRの既存の外部ライブラリ利用は継続しています。
