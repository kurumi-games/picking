## ver54 — 写真を参考にリフトを配置

地図の区画名が「リフト」（または「フォークリフト」）の場所を、黄色い立ち乗りリフトに置き換えました。写真6330.jpgを参考にした曲面の車体、番号09、黒いマスト、曲がった屋根支柱、車輪、操作部、下げたフォークを描画します。箱や荷物は追加しません。ロゴや微細な機構、実寸までの完全再現ではありません。

既存の登録区画の長辺に車体を合わせ、フォークも含めて区画内へ収めます。向きは区画の形から決めた近似です。固定された駐車状態で、走行・荷役操作は追加していません。地図・部品・天井番号の保存データ、区画の位置や通路判定は従来どおりです。

最新版ver53.1の棚の縦向き設定を引き継いでいます。リフト以外の棚・扉・パレット・床・照明の描画は変更していません。画像素材や外部ライブラリの追加もありません。

`tests/lift-browser.cjs` はPlaywrightで、配置・接地・区画内への収まり・登録区画が1つであることを検証します。`BASELINE_WORLD` に変更前のwarehouse3d.jsを渡すと、リフト区画以外の描画と全区画の通行判定が変更前と一致することも比較します。

## ver53 — 棚番区画と扉のみ変更

「棚番の品」という名前の区画だけを、灰色のアングル支柱と棚板5段の棚4列に変更しました。箱・部品は描画しません。棚の間は歩けますが、保存上は従来どおり一つの区画であり、棚段単位の登録は追加していません。他の区画・パレット・照明の形や配置は変更していません。

4列は確認済みです。列の長手方向は地図の左右、列間はパレット約1枚分を**仮設定**しています。寸法や方向は `warehouse3d.js` の `shelfSettings` にまとめています。`direction: 'x'` が左右、`'z'` が上下です。`aisle: 4` はパレット1枚分の描画単位であり4mではありません。狭い区画では、はみ出さないよう幅・間隔を縮小します。

地図の `type: 'door'` の場所に、金属枠・上半分のすりガラス・下半分の金属板・丸いノブ・ドアクローザーを追加しました。写真を参考にした閉じた片開きドアの外観です。開閉アニメーションや移動判定の変更はありません。

新しい保存データや初期化処理はありません。部品検索・赤矢印・場所登録・複数フロアは既存の処理を使います。3D内の小地図と確認版の全体図には棚の間の通路を表示しますが、本体の2Dマップや保存される区画の形は変更しません。

`tests/fixtures-browser.cjs` はPlaywrightで4列・5段・通路の接続・区画が1つであることを確認します。`BASELINE_WORLD` に変更前の `warehouse3d.js` を指定すると、棚番区画と扉以外の描画要素が変更前と一致することも比較します。

## ver51 — 写真を参考にした質感

床・壁・天井の素材と照明、パレットの形を更新しました。緑の塗装床には傷や塗装のむらがある画像素材を使用し、低解像度の床反射を重ねます。小地図の「床の反射」でON/OFFを切り替えられます。天井には板の継ぎ目、配管、2本組の蛍光灯を追加しました。パレットには成形された縁とフォーク用の隙間があります。地図上のシャッターは黄色い織目のある幕として表示します。

`texture-preview.html` は質感を確認するための独立したサンプルです。仮の通路を使用し、保存済みデータには触れません。本体はこれまでどおり端末に保存された地図を使います。

提供された通常写真を参考にした3D表現です。写真をそのまま360°につないだ表示ではなく、写真に写っていない場所・実寸・窓や設備の位置を復元していません。今回の天井は低い室内の写真を参考にしており、鉄骨の高い別区画までは再現していません。部品の外観を描画しないため、部品が入れ替わっても背景写真の撮り直しは不要です。

新しい画像素材2枚は合計約355KBです。蛍光灯の光源はカメラ近傍の最大6個に制限しています。Pixel実機の速度は未計測なので、重い場合は床の反射をOFFにしてください。素材の出典・作成方法は `img/warehouse/README.md` を参照してください。

## ver50 — 倉庫ストリートビュー

「マップ」→「倉庫ストリートビューを開く」。保存済みの地図を使い、通路の目線で倉庫を歩けます。「3D」→「歩く」からも開けます。

- 画面をスワイプして見回し、床の矢印をタップして移動。左下の方向ボタンの長押しでも歩けます。PCはWASD、矢印キーに対応します。
- 右下の小さな地図で緑の通路をタップすると、棚を避けてその位置へ移動します。つながっていない通路への通常移動はできません。
- 「部品」でコードを入力・貼り付け、または数字パッドで検索すると、登録場所の近くへ移動し、赤い矢印と枠で場所を示します。複数の登録先は「次の場所」で順に表示します。別フロアにも対応します。
- 「＋ 場所登録」→黒いパレットをタップ→コードと置き方を入力→「ここに登録」。既存のほかの登録場所は残ります。同じコード・同じ位置は置き方を更新します。移動元の解除は「全体」→部品を検索→「場所を移動・解除」で行えます。
- 地図のパレット表示1個＝内部の方眼2×2マス。区画の端では幅・奥行きを切り詰め、地図と一致させます。パレットが表示されない区画は、2Dマップで選択して「3D形状」から設定できます。
- 「棚番の品」のようにまとめて描いた区画は、一つの区画として表示します。個別の棚や棚段は推測しません。

この表示は**地図を基準にした3Dモデル**です。写真の緑の床・黒い樹脂パレット・蛍光灯を参考に外観を作っており、実写360°写真や写真測量による再現ではありません。高さや建物の外観は模式的です。私物の写真や動画は含みません。

部品・箱の外観は背景に含めないので、部品が入れ替わっても撮り直し不要です。実物を移動したときは場所の登録を更新してください。地図そのものやパレットの配置が変わった場合は、地図の更新が必要です。赤い矢印は登録された平面位置を示し、棚段や在庫数量を保証するものではありません。

## 既存データ

保存先はこれまで通りブラウザのlocalStorage（`pickingDB_v1`）です。アップデートで既存の地図・部品・天井番号を初期化しません。画像で送られた地図を別の初期地図に置き換えることもありません。複数端末の自動共有はありません。

C4765とC00004765は同じ部品として検索できます。別品番への誤案内を避けるため、ゼロ埋めを除いた完全一致です。明示的に解除した場所を旧形式の棚情報から復活させません。

3DエンジンはThree.js r128をvendor配下に同梱しています。GitHub PagesのHTML/JSのみで動作し、3D用のサーバーや外部APIは不要です。バーコード・OCRの既存の外部ライブラリ利用は継続しています。
